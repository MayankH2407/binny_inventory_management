# Phase 19 — Audit Log, Inventory Transactions & Cross-Module Integrity

**Module codes:** `AUD`
**Roles under test:** Admin (`admin@binny.com` / `Admin@123`), Supervisor (`supervisor@binny.com` / `Sup@123`)
**Backend API base:** `http://localhost:5000/api/v1`

**Schema notes:**
- `audit_logs` table columns: `id`, `user_id`, `action`, `entity_type`, `entity_id`, `old_values` (JSON), `new_values` (JSON), `ip_address`, `user_agent`, `created_at`. Written by `auditLog.service.ts` `createAuditLog()`. Failures are swallowed (do not break the main operation).
- `inventory_transactions` table columns: `id`, `transaction_type`, `child_box_id` (nullable), `master_carton_id` (nullable), `performed_by`, `notes`, `metadata` (JSON), `created_at`. Exposed via `GET /api/v1/inventory/transactions`.
- **No dedicated `GET /api/v1/audit-logs` route is mounted** (checked `routes/index.ts` — no `auditLog.routes` registered). Audit log verification must be done directly against the DB or via a DB admin query.
- `GET /api/v1/inventory/transactions` is authenticated but **not role-restricted** (`inventory.routes.ts` applies only `authenticate`).

**Key invariant for all state-changing actions:** each action writes the expected `inventory_transactions` row(s). Verify with `GET /api/v1/inventory/transactions?child_box_id=<id>` or `?master_carton_id=<id>`, or by querying the DB: `SELECT transaction_type, created_at FROM inventory_transactions WHERE child_box_id = '<id>' ORDER BY created_at`.

**Dependencies:** Phases 03–13 (all entity creation flows).
